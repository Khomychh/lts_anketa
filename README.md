# Вступна анкета — Львівська Богословська Семінарія

Односторінковий сайт для збору анкет вступників. Чистий HTML/CSS/JS, без фреймворків
і без збірки. Відповіді потрапляють у Google Таблицю через Google Apps Script.

## Що всередині

| Файл | Призначення |
|---|---|
| `index.html` | Уся сторінка: розмітка, стилі, скрипт, логотип (інлайн SVG). Самодостатній файл. |
| `Code.gs` | Google Apps Script: приймає POST і дописує рядок в аркуш «Заявки». |
| `logos/` | Вихідні файли логотипа. Сторінці не потрібні — емблема вже вшита в `index.html`. |

## Як це працює

Анкета розбита на **6 розділів** — по одному екрану за раз, з індикатором прогресу.
Обовʼязкові лише шість полів: ПІБ, телефон, email, програма, форма навчання і згода
на обробку даних. Решту можна пропустити.

Дані йдуть одним запитом при натисканні «Надіслати анкету»:

```js
fetch(GOOGLE_SCRIPT_URL, { method: 'POST', mode: 'no-cors', body: formData })
```

Через `mode: 'no-cors'` відповідь сервера непрочитувана (opaque), тому екран подяки
показується оптимістично — одразу після того, як `fetch` не кинув виняток.

**Захист від ботів.** У формі є приховане поле `website`, винесене за екран
(`left:-9999px`, не `display:none`), з `tabindex="-1"` і `autocomplete="off"`.
Якщо воно заповнене, запит просто не надсилається, а користувач бачить звичайний
екран подяки. Apps Script додатково перевіряє це поле на своєму боці.

**Фото.** Файл не можна передати у `doPost(e)` через `e.parameter`, тому браузер
зменшує зображення до 900 px і кладе його у приховане текстове поле `photo` як data URL.
Apps Script декодує його, зберігає файл у папку Drive «Анкети — фото» і записує
в таблицю посилання.

**Прапорці «Звідки дізналися».** Кілька позначок обʼєднуються в одне значення
через кому, щоб зайняти одну колонку таблиці.

**Логотип.** Емблема вшита в `index.html` як `<g id="lts-emblem">` усередині `<defs>`,
а виводиться через `<use>` у шапці сторінки. Колір береться з `currentColor`, тож на
металевому тлі вона біла, і жодних зовнішніх файлів не потрібно.

> Якщо будете міняти емблему: обгортка має бути саме `<g>`, а не `<symbol>`.
> `<symbol>` створює власний viewport, і тоді обрізка з `viewBox` застосовується
> двічі — видно лише куточок логотипа.

## Розгортання

### 1. Google Apps Script

1. Створіть Google Таблицю — сюди збиратимуться заявки.
2. У ній: **Розширення → Apps Script**.
3. Замініть вміст `Code.gs` на вміст файлу `Code.gs` із цього репозиторію. Збережіть.
4. **Deploy → New deployment → тип Web app**:
   - *Execute as*: **Me**
   - *Who has access*: **Anyone**
5. Підтвердьте доступ до Таблиці й Диска (Google покаже екран «Advanced → Go to project»).
6. Скопіюйте URL виду `https://script.google.com/macros/s/……/exec`.

Перевірка: відкрийте цей URL у браузері — має відповісти
`{"result":"success","message":"Приймання анкет працює."}`.

Аркуш «Заявки» і рядок заголовків створяться автоматично при першій заявці.

### 2. index.html

Відкрийте `index.html`, знайдіть рядок

```js
const GOOGLE_SCRIPT_URL = "PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
```

і вставте туди свій URL із кроку 1.

### 3. Публікація

Сторінка статична — підійде будь-який хостинг. Найпростіші варіанти:

**GitHub Pages**
```bash
git init && git add index.html && git commit -m "Вступна анкета"
git branch -M main
git remote add origin https://github.com/<користувач>/<репозиторій>.git
git push -u origin main
```
Далі **Settings → Pages → Source: Deploy from a branch → main / root**.

**Netlify або Vercel** — перетягніть теку з `index.html` у вікно drag-and-drop,
або підключіть репозиторій. Команда збірки не потрібна, publish directory — корінь.

**Власний хостинг** — просто покладіть `index.html` у корінь сайту.

Локальний перегляд:
```bash
python -m http.server 8000
```
і відкрийте `http://localhost:8000`. Через `file://` сторінка теж працює,
але шрифти Google Fonts не завантажаться.

## Зміна полів

Список полів заданий у двох місцях і має збігатися:

- в `index.html` — атрибут `name` у кожного поля;
- в `Code.gs` — масив `FIELDS`, де `key` це той самий `name`, а `header` — заголовок
  колонки в таблиці.

Додаючи поле, впишіть його в обидва місця. Порядок у `FIELDS` задає порядок колонок.

> Якщо аркуш «Заявки» вже створено, новий заголовок у ньому не зʼявиться сам —
> або допишіть колонку вручну, або перейменуйте аркуш, щоб скрипт створив новий.

## Технічні деталі

**Дизайн** зроблено за зразком `Анкета зразок.jpg`: металеве сіро-срібне тло на весь
екран, білий текст, поля лише з нижньою лінією (без рамок і карток), чорна pill-кнопка
головної дії і біла — другорядної, квадратний чекбокс згоди.

Виняток — три довгі відповіді в розділі «Мотивація»: підпис стоїть **над** полем, а саме
поле росте під текст (`.f.area`, автовисота в JS). З плаваючим підписом текст починався
вгорі, а лінія висіла за сотню пікселів нижче — порожнеча між ними читалася як помилка.

Тло — це `div.bg` з `position:fixed`: діагональний `linear-gradient` зі сріблястих сірих,
тепле світло згори праворуч і напівпрозорий темний шар поверх, щоб білий текст лишався
читабельним (у самому зразку контраст для цього замалий). Тло не прокручується разом
з формою.

**Шрифт.** **Montserrat** з Google Fonts і підстраховкою системними — геометричний, як
на зразку, і має кирилицю (Poppins, найближчий за формою, кирилиці не має). Поля вводу
мають розмір 16 px — це не дає iOS Safari підсмикувати масштаб при фокусі.

**Верстка mobile-first.** Базові правила описують телефон, усі медіазапити — лише
`min-width`.

| Ширина | Що змінюється |
|---|---|
| базово (телефон) | одна колонка до 520 px, кнопки на всю ширину стовпчиком: головна дія зверху, «Назад» під нею |
| від 600 px | більші відступи й заголовок, колонка до 600 px, кнопки стають у рядок |
| від 1000 px | колонка до 660 px, заголовок 46 px |

Кнопки навігації стоять у природному кінці розділу, а не липнуть до низу екрана:
на телефоні липка кнопка лягала поверх першого поля форми.

**Прогрес** показують шість сегментів під шапкою — по одному на розділ; вони
оновлюються у функції `paint()`.

**Темні елементи керування.** `color-scheme:dark` на `:root` — щоб календар
`input[type=date]` і випадний список `select` малювалися темними, а не білими
плямами на градієнті. Там же правило проти білої заливки автозаповнення Chrome.

**Доступність.** Видимий фокус з клавіатури, `prefers-reduced-motion`, Enter у полі
веде до наступного розділу, фокус при переході стає на заголовок розділу, помилки
пишуть, що саме виправити. Прозорість білого для другорядного тексту й ліній винесена
в CSS-змінні (`--dim`, `--dimmer`, `--line`) на початку `<style>` — правити контраст
можна в одному місці, разом із затемненням у `.bg`.

**Телефон** перевіряється за кількістю цифр (9, 10 або 12), а не за жорстким шаблоном,
тож `0671234567`, `+380 67 123 45 67` і `+38 (067) 123-45-67` однаково приймаються.

**Перевірено** в Chrome на ширинах 360, 390 і 1300 px: усі шість розділів, валідація,
екран подяки. Підтримка браузерів: усі актуальні (Chrome, Safari, Firefox, Edge).
IE не підтримується.
